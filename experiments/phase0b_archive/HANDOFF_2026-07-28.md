### THE EXACT OPEN QUESTION
The CANONICAL_grid_n300 run collapsed null_a (1/18) — which CONTRADICTED the
N=100 bare_nosys run (all 6 bistable). Root cause found by diffing the two
prompts: the ONLY difference is the null_a task-instruction block that the
phase0b runner prepends:

    "You are participating in a decision-making simulation.
     # Your task
     You will be presented with a decision. Apply a consistent decision-making
     rule to the decision below. Do not infer demographic identity, ...
     Do not refuse to decide. Answer in the exact format specified."

The bistable bare_nosys run had NO such block (dilemma only). So the collapser is
this task text — prime suspect the word **"consistent"** in "apply a CONSISTENT
decision-making rule" (a determinism cue that kills the coin-flip). NOT the
delivery envelope (that was an earlier, partially-wrong hypothesis).

### TENSION to resolve (why it's a real decision, not a trivial edit)
That task block is structurally WHERE Phase 2 injects the parameter profile
("apply the decision-making profile as a decision rule..."). So null_a must keep
the block's STRUCTURE to remain a valid control — we can't just delete it, or
null_a stops resembling the Phase 2 harness.

### WHY the reword is rigorous, not a cop-out
The thesis claims PARAMETERS produce behaviour. An instruction hardcoding
"be consistent" is a rival explanation competing with the parameters. Removing it
removes a confound. That is rigor.
